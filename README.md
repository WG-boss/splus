# S++ 指数投研管理系统 · 操作手册

> 本系统把「国际顶级投研的组织与认知框架」落成 WindClaw 里可运行、可复算、可审计的配置与代码。
> 定位：**不是预测工具，是把“该不该动手、动手多少、错了怎么退”变成纪律。**

---

## 一、它解决什么问题

散户做指数投资最常见的三个失误：

1. **用估值代替结构**——PE 处于历史 4% 分位就加仓，但价格还在创新低。
2. **用分散代替风控**——买三个科技指数以为分散了，实际相关性 0.8，是一个仓位。
3. **用判断代替纪律**——没有“涨到什么位置才允许动手”的前置条件，在下跌通道里反复抄底。

本系统逐条对冲这三点：状态概率（结构优先）、桶内合并（真分散）、触发位+失效位（纪律）。

## 二、目录结构

```
splus/
├── splus_config.yaml      ← 唯一口径来源，所有阈值都在这里，改规则只改它
├── engine.py              ← L1~L5 引擎（状态/传导/仓位/执行/风险）
├── meta_layer.py          ← L6 元层（概率校准台账）
├── run.py                 ← 一键运行，输出 Markdown + JSON
├── selftest_states.py     ← 状态区分能力自测（合成行情）
├── selftest_history.py    ← 真实数据回溯 + 参数敏感性
├── data/
│   ├── splus_decision_YYYYMMDD.json   ← 结构化决策（供机器读）
│   ├── splus_report_YYYYMMDD.md       ← 人读报告
│   └── ledger/predictions.jsonl       ← 预测台账（追加写，不可变）
└── state/last_state.json  ← 上一交易日概率，用于贝叶斯先验
```

数据源复用 `../stock-pool/_cache/` 的指数 K 线缓存，无需重复抓取。

## 三、日常使用

```bash
cd splus
python run.py                 # 生成当日决策
python selftest_states.py     # 改参数后必跑：验证状态区分能力
python selftest_history.py    # 月度体检：看切换频次与参数敏感性
```

**改参数的唯一正确顺序：**

1. 先改 `splus_config.yaml`
2. 跑 `selftest_states.py`——五类状态必须仍全部 PASS
3. 跑 `selftest_history.py`——切换频次不能变得过高
4. 再跑 `run.py` 出正式结论

**顺序不能反。** 先出结论再调参数，等于把回测当成了证据。

## 四、六层结构（每层负责什么、不负责什么）

| 层 | 回答的问题 | 输出 | 明确不负责 |
|---|---|---|---|
| **L1 状态** | 现在处于什么阶段 | 五状态概率向量 + 置信度 | 不判断该配多少 |
| **L2 传导** | 上游动了吗 | 领先滞后天数 + 相关性矩阵 | 不直接给仓位数 |
| **L3 仓位** | 该配多少 | vol目标×回撤×相关性×状态权重 | 不判断方向 |
| **L4 执行** | 何时允许动手 | 触发位 / 追价上限 / 失效位 | 不判断该不该配 |
| **L5 风险** | 什么时候必须停手 | KILL SWITCH + 压缩系数 | 不判断买什么 |
| **L6 元层** | 这套系统还准吗 | Brier score + 校准曲线 | 不参与当期决策 |

## 五、五状态定义（可证伪口径）

每个状态都有**必须项（gate）**，不满足就大幅压分。这是防止误判的核心设计。

| 状态 | 含义 | 必须项 | 关键确认特征 |
|---|---|---|---|
| **A 吸筹/筑底** | 深跌后横盘蓄势 | 回撤 ≥18~40% | 波动收敛、区间收窄、缩量、贴近长期均线 |
| **B 突破/启动** | 放量突破前高 | 当日确为突破日 | 量能 Z>1、3日站稳、接近新高 |
| **C 趋势通道** | 稳定上行 | 价在长期均线上+均线上行 | 高效率、ADX>20、高低点抬升、均线多头 |
| **D 区间/派发** | 高位滞涨 | 处于高位（回撤<15%） | 效率衰减、下跌放量、假突破频发 |
| **E 下跌/衰退** | 单边下行 | 价在长期均线下**或**均线转平向下 | 高效下跌、高低点下移、价在短均线下 |

**E 阶段的子状态（关键）**：E 可持续数月，但"下跌中继"与"下行中的可交易反弹"完全不同。
系统用四项打分（站上EMA20 / EMA20>EMA60 / 效率抬升 / 放量），≥3 项才认定为**可战术参与**的反弹。

**当前实测（2026-10-22）：所有标的 rebound 评分 0–1，无一达到 3 项门槛 → 全部为"下跌中继，不参与"。**

## 六、仓位三重约束（取最小值）

```
最终仓位 = min(波动率目标约束, 回撤节流约束, 相关性惩罚) × 状态权重
```

| 约束 | 公式 | 示例（科创50，vol 35%） |
|---|---|---|
| ① 波动率目标 | 15% ÷ 年化波动率 | 15%÷35% = 43% |
| ② 回撤节流 | 组合回撤 0–5%→1.0；5–10%→0.75；10–15%→0.5；15–20%→0.3；>20%→0.15 | 回撤 0 → 1.0 |
| ③ 相关性惩罚 | 均值 >0.7 起罚，斜率 1.5 | 当前 0.59 → 1.0 |
| ④ 状态权重 | A 0.25 / B 0.85 / C 0.90 / D 0.40 / E 0.10 的概率加权 | E 主导 → ~0.14 |

**桶内合并才是真分散**：`core`（科创50+创业板50+恒生科技）按最高波动率计一个仓位上限，不分别计。

## 七、风险开关（会真实压缩仓位，不是展示）

| 开关 | 触发条件 | 动作 |
|---|---|---|
| `SYS_CORR` | 三指数相关性 >0.8 且有≥2个深度回撤 | 冻结新增多头 |
| `BROAD_E` | ≥2 个可交易指数处于 E 阶段 | 禁止左侧加仓；总敞口 ×0.5 |
| `UPSTREAM_WEAK` | 上游 20 日跌幅 >8% | 禁止左侧试探仓 |
| `THEME_CAP` | E 阶段下主题桶超限 | 主题桶硬顶 6% |

**当前生效：`BROAD_E`（5/5 可交易标的处 E 阶段）→ 总敞口压缩系数 0.5。**

## 八、L6 元层：怎么知道这套系统还准

- 每次运行写入 `predictions.jsonl`（预测 + 当时的概率）
- 20 个交易日后自动结算：B/C 看多→收益>0 记命中；E 看空→收益<0 记命中；A/D→|收益|<5% 记命中
- 累计 ≥30 条后输出 Brier score 与校准曲线
- **Brier >0.28 或平均校准偏差 >0.10 → 告警，所有依赖概率的仓位计算降权**

**当前状态：已结算 0 条，样本不足，不下结论。** 这是诚实的起点——不能拿 0 条数据说自己准。

## 十、参数优化与显著性检验

调参最危险的失败模式不是“调不出好结果”，而是“调出好看的数字并当真”。
本模块的默认结论是**不建议修改**，除非四项门槛全过。

```bash
python optimize.py           # 网格搜索 + 走前向验证
python sig_test2.py          # 时间块 bootstrap 显著性检验
python selftest_optimize.py  # 验证这套流程本身能检出真信号（10/10）
```

**必须知道的陷阱**：`STEP=5` + `HORIZON=20` 意味着相邻样本共享 15 天收益，
163 条名义样本的有效独立样本只有约 40 条。在 40 条上做 81 组搜索，是最典型的过拟合配方。

**判定门槛（写死在代码里，不许事后改）**：OOS AUC 提升 ≥ +0.02 **且** 95% CI 下界 > 0
**且**方向命中率 > 0.5，四项缺一不可。

**2026-10-23 实测结论：四项过三，不改配置。**
提升真实存在（AUC 0.6591 → 0.6731，p=0.008，CI [+0.0044, +0.0261]），
但 +0.014 的改善落在执行噪声里，不足以改变任何一次建仓决策。
详见 `OPTIMIZE_REPORT.md`。

## 十一、报表输出

```bash
python run.py    # 一次生成三件：JSON（全量决策）、Markdown（终端友好）、HTML（自包含）
```

HTML 为单文件自包含（CSS 内联、无外链、不联网），额外提供**概率条形图**——
这是终端看不到的信息，也是三个产物里唯一值得用浏览器打开的。

渲染器有输入完整性校验：残缺 `res` 会抛异常，而不是静默产出“表格齐全但内容全空”的报告。
后者不会报错、不会告警，只在人真的去读时才暴露，是比崩溃更危险的失败模式。

## 十二、已知局限（必须知道）

1. **状态判定本质滞后。** 五状态在事后清晰，事中永远有"D 还是 C"的模糊地带。系统用概率向量 + 置信门槛应对，不追求判定绝对准确。
2. **失效价在 E 阶段参考意义有限。** 因价格距触发位尚有 24%–48%，失效位远在下方。它是"若已持仓"的止损参考，不是入场依据。
3. **传导链时滞为实测值，非理论值。** 当前纳指100 对 A 股领先滞后多显示 0–1 日，说明该 edge 已被充分套利，**不可作为独立 alpha 来源**。
4. **PE 分位未纳入模型。** 有意为之——估值分位是"便宜"的度量，不是"会涨"的预测；本轮创业板50 PE 4.3% 分位仍创新低就是证据。估值只作为人工复核项。
5. **恒生科技数据口径待核。** Wind 报 3249.12，腾讯行情与 K 线缓存一致为 3784.58。系统采用缓存口径并在报告披露，**结论请以核实后的数据为准**。
6. **参数未经长期样本校准。** 所有阈值是经验起点，必须用自身样本重跑 `selftest_history.py` 后再定。

---

## 十一、这套系统不做什么

- 不预测点位
- 不产生 alpha（公开方法 + 公开数据 = 无 edge）
- 不替代产业跟踪（主题指数的方向必须来自产业研究，PA 只管时机与风控）
- 不保证收益

**它做的是：让你在该不动的时候真的不动，在该退的时候退得干脆。**
